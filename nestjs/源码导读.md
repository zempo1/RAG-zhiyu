# 后端源码导读

后端由 `nestjs/` 和 `services/pdf-analysis/` 组成。NestJS 提供 HTTP API 和任务执行，Python 服务负责本地 PDF 版面识别和 OCR。启动和数据库升级见 [后端 README](README.md)。

## 模块索引

| 模块 | 职责 | 读代码的入口 |
| --- | --- | --- |
| `agent` | 组织文档问答工作流、工具、证据和断点恢复 | [agent.service.ts](src/modules/agent/agent.service.ts) |
| `analysis` | 生成并管理文档摘要和学习闪卡 | [analysis.service.ts](src/modules/analysis/analysis.service.ts) |
| `auth` | 注册、登录、账号维护和 JWT 校验 | [auth.service.ts](src/modules/auth/auth.service.ts) |
| `chat` | 编排同步和流式问答，管理任务受理与收尾 | [chat-workflow.service.ts](src/modules/chat/chat-workflow.service.ts) |
| `documents` | 上传、原件预览、文档版本和建索引 | [documents.service.ts](src/modules/documents/documents.service.ts) |
| `embeddings` | 文本向量生成、模型配置识别和 Token 计数 | [embeddings.service.ts](src/modules/embeddings/embeddings.service.ts) |
| `history` | 管理会话、消息和历史引用 | [history.service.ts](src/modules/history/history.service.ts) |
| `knowledge-bases` | 管理知识库、分类和访问范围 | [knowledge-bases.service.ts](src/modules/knowledge-bases/knowledge-bases.service.ts) |
| `llm` | 调用补全、流式生成与视觉模型 | [llm.service.ts](src/modules/llm/llm.service.ts) |
| `mindmaps` | 受理导图任务，保存并管理导图结果 | [mindmaps.service.ts](src/modules/mindmaps/mindmaps.service.ts) |
| `model-settings` | 管理账号模型设置与任务执行时的模型上下文 | [model-settings.service.ts](src/modules/model-settings/model-settings.service.ts) |
| `quizzes` | 题集、答题练习、错题复习和关联问答 | [quizzes.service.ts](src/modules/quizzes/quizzes.service.ts) |
| `rag` | 混合检索、证据打包、引用和诊断记录 | [retrieval.service.ts](src/modules/rag/retrieval/retrieval.service.ts) |
| `tasks` | 后台任务状态、队列、取消和重试 | [task-queue.runtime.ts](src/modules/tasks/queue/task-queue.runtime.ts) |
| `vector-store` | 提供内存和 Qdrant 向量存储实现 | [vector-store.interface.ts](src/modules/vector-store/vector-store.interface.ts) |

## 按业务场景阅读

1. **上传、替换和建索引。** 上传入口接收完整文件或分片，文档服务建立版本与任务。Worker 执行解析、切块、嵌入和向量写入，全部成功后发布索引。替换或重建时保留当前可查询版本直到新索引发布。[上传入口](src/modules/documents/upload/document-upload.controller.ts) · [文档服务](src/modules/documents/documents.service.ts) · [索引处理](src/modules/documents/indexing/indexing.service.ts)
2. **提问、生成和保存会话。** 问答流程校验请求及会话，按证据规模决定直接执行或交给后台。Agent 与 RAG 准备证据，问答服务组织同步或流式输出，历史服务保存消息及引用快照。[问答编排](src/modules/chat/chat-workflow.service.ts) · [Agent](src/modules/agent/agent.service.ts) · [检索](src/modules/rag/retrieval/retrieval.service.ts) · [会话历史](src/modules/history/history.service.ts)
3. **点击引用回到 PDF。** 解析阶段写入来源位置，检索与引用模块保留段落、表格和跨页证据。原件入口校验文档及版本归属，提供文件、页图和引用上下文。[来源坐标](src/modules/documents/parsers/pdf/layout/source-anchors.ts) · [引用模块](src/modules/rag/citations/) · [原件入口](src/modules/documents/originals/document-assets.controller.ts) · [阅读器指南](../docs/pdf-source-viewer.md)
4. **生成摘要、闪卡和导图。** 摘要和闪卡由分析服务处理。导图服务先受理任务，生成目录负责预算与分批、模型调用、树组装、任务恢复和发布。新生成结果和用户编辑使用同一套导图结构校验。[分析服务](src/modules/analysis/analysis.service.ts) · [导图服务](src/modules/mindmaps/mindmaps.service.ts) · [导图生成](src/modules/mindmaps/generation/)
5. **生成测验、答题和整理错题。** 测验生成按来源挑选材料并校验题目证据。题集与普通答题从主测验接口进入，已提交的错答进入错题复习，可手动分类或生成变式练习。[测验生成](src/modules/quizzes/generation/) · [答题入口](src/modules/quizzes/quiz-attempts.controller.ts) · [错题复习](src/modules/quizzes/reviews/)
6. **账号模型配置如何传进任务。** 请求拦截器加载账号配置，运行时解析模型用途、密钥和环境默认值。需要异步继续的任务保存模型快照，Worker 恢复后继续使用受理时的配置。[模型设置](src/modules/model-settings/model-settings.service.ts) · [运行时上下文](src/modules/model-settings/runtime/model-runtime.ts)
7. **API、Worker 和数据库如何配合。** BullMQ 模式下，API 受理请求并写入任务记录，队列运行时扫描存储并补投，Worker 消费队列任务。内存模式下，API 进程直接执行任务。检索记录清理在 BullMQ 模式由 Worker 调度，在内存模式由 API 调度。已有数据库通过项目脚本显式迁移。[应用装配](src/app.module.ts) · [队列运行时](src/modules/tasks/queue/task-queue.runtime.ts) · [检索记录保留](src/modules/rag/retrieval-runs/retrieval-runs-retention.ts) · [数据源](src/persistence/data-source.ts)

## 文件放置约定

- 在所属功能模块保留 `*.module.ts` 作为 NestJS 装配入口。Controller 负责 HTTP 或 SSE，Service 负责用例与业务编排。
- DTO 放进 `dto/`，数据库实体放进 `entities/`。单一职责的小模块继续把入口和实现放在模块根目录，形成独立流程的文件按功能成组，例如 `generation/`、`reviews/`、`runtime/`。
- 同一模块中被多个流程使用的数据结构与校验放在根目录，例如 `mindmap-data.ts` 和 `quiz-data.ts`。通用 HTTP 组件放在 `common/`，数据库结构变更放在 `persistence/migrations/`。
- 业务文件移动时同步检查源码导入、手工脚本中的构建路径和导读链接。测试文件继续放在现有 `test/` 位置。
